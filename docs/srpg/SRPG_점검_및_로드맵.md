# SRPG 프로젝트 점검 및 로드맵

> 작성일: 2026-04-13 · 대상 코드: `Assets/Scripts/SRPG/` (25개 스크립트)

## 1. 현재 상태 요약

### 완성된 기능

| 영역 | 구현 내용 |
|------|-----------|
| **전투 코어** | 비정사각형 그리드, BFS 이동(ZOC 가중), 8방 체비쇼프 공격, AP/HP/PG/그로기/처단 |
| **턴 관리** | 자유 이동/공격 순서, 유닛별 행동 완료 추적, Undo(스냅샷 기반), 턴 종료·승패 판정 |
| **스킬 기초** | 액티브 스킬(Self/단일 대상) 사용, 쿨다운 Tick, 일부 패시브(턴 시작·공격 적중) |
| **HUD** | 좌우 사이드 패널, TMP 기반 로그 스크롤, 스킬 슬롯·Tooltip, 한글 글리프 프리로드 |
| **메이커 3종** | 스킬/유닛/맵 CRUD, 맵 메이커 카메라·풋프린트·유닛별 스킬 비활성화 |
| **인프라** | 로비 씬 분리, JSON 영속화(`persistentDataPath`), DevTools(F3), 기본 맵·스킬·유닛 시드 |

### 부분 구현 — 즉시 점검 필요

| # | 항목 | 현황 | 문제 |
|---|------|------|------|
| **P1** | `disabledSkillIds` | 맵 메이커에서 저장됨 | 전투 시 스킬 사용 시점에서 **검증 로직 없음** — 비활성화 의미 없음 |
| **P2** | `allowedSkillIds` | `SrpMapFileV1` 스키마에 존재 | 코드 어디서도 **참조되지 않음** — 데드 필드 |
| **P3** | `OnTakeDamage` 트리거 | `SrpSkills.OnTakeDamage()` 정의됨 | **호출부 없음** — 반격/피격 패시브 작동 불가 |
| **P4** | `duration` (효과 지속) | `SrpSkillEffect.duration` 필드 존재 | **버프 만료·턴 차감 로직 없음** — 영속 버프만 가능 |
| **P5** | 범위 스킬 (`areaSize`) | 타겟 타일 나열까지 구현 | `ResolveActiveSkill`이 **단일 `GetOccupant`에만 효과 적용** — 범위 효과 미반영 |
| **P6** | `maxSkills` 제한 | 유닛 메이커 UI에서만 제한 | `CreateUnitFromTemplate`이 **전체 skillIds를 그대로 복사** — 런타임 미검증 |

### 미구현 — GDD/TDD에 기술되었으나 코드 없음

- AI 스텁 (무작위 합법 수)
- FH(처형장) 확장 규칙
- 다양한 승패 조건 (턴 제한, 거점 점령 등)
- 멀티플레이어 / 원격 세션
- `Resources/SrpMaps/` 읽기 전용 배포 맵

## 2. 아키텍처 점검

### 장점

- **상태 분리**: `SrpBattleState`가 Unity 비의존에 가깝게 시뮬레이션 상태를 관리하여 테스트 가능성 확보.
- **Partial 분할**: `SrpGameController`를 전투/HUD/렌더링 3파일로 나누어 도메인 충돌 최소화.
- **데이터 주도**: 스킬·유닛·맵 모두 JSON 직렬화 기반으로 외부 편집 가능.

### 개선이 필요한 부분

| 영역 | 현황 | 권장 방향 |
|------|------|-----------|
| **메이커 코드 비대화** | MapMaker 1026줄, SkillMaker 827줄, UnitMaker 738줄 | UI 빌더 공용 유틸 추출 (드롭다운·스크롤·입력 필드 생성 헬퍼) |
| **GameController 오케스트레이터 비대** | 3 partial 합계 ~1118줄. 스킬/AI 추가 시 더 비대해질 위험 | Phase별 핸들러 클래스 분리 검토 (당장은 아니지만 ~1500줄 넘으면 착수) |
| **UI 중복** | 메이커·로비 모두 uGUI 코드 생성 패턴 반복 | `SrpUiBuilder` 정적 헬퍼 도입 — 드롭다운, 버튼, 입력 필드 원샷 생성 |
| **프리팹 부재** | 전부 코드 생성 → 디자이너 협업·스킨 교체 어려움 | 단기적으로는 현행 유지 가능. 비주얼 고도화 시 타일/유닛 프리팹 전환 |
| **테스트 부재** | 자동화 테스트 0개 | 전투 코어(`BattleState`, `CombatResolver`, `Pathfinder`)부터 EditMode 테스트 추가 |
| **인스펙터-Awake 불일치** | `leftPanelWidth`/`rightPanelWidth` 필드 기본값 630이지만 `Awake`에서 370으로 덮어씀 | 한쪽으로 통일 (필드 기본값 370 or Awake 제거) |
| **문서 간 미세 불일치** | TDD의 DB 파일명과 실제 `SrpDataIO` 경로 표기 차이 | TDD v0.6 갱신 시 경로 표 재확인 |

| 2 | `OnTakeDamage` 호출 연결 | ★☆☆ | `SrpCombatResolver.ResolveAttack` 결과 후 피격 유닛에 호출 |

## 4. 추천 로드맵

```
Phase 0  지금  ─────────────────────────────────────────────────
Phase 1  기반 다지기 (1~2주)
Phase 2  스킬 시스템 v2 (2~3주)
Phase 3  AI 기초 (1~2주)
Phase 4  콘텐츠 & 밸런스 (지속)
Phase 5  비주얼 고도화 (2~4주)
Phase 6  멀티플레이어 (장기)
─────────────────────────────────────────────────────────────
```

### Phase 0: 즉시 점검 (Now)

> 목표: 이미 있는 데이터와 코드 사이의 **간극 제거**

- [ ] Quick Wins §3 항목 전부 처리
- [ ] 스킬메이커 개선 설계문서(`PLAN_스킬메이커_개선.md`) 최종 확정

### Phase 1: 기반 다지기 (1~2주)

> 목표: 이후 기능 추가 시 **안정성·생산성** 확보

| 항목 | 내용 |
|------|------|
| **EditMode 테스트** | `BattleState`, `CombatResolver`, `Pathfinder`에 대한 유닛 테스트. 이동 비용·ZOC·데미지 공식·경로 탐색 검증 |
| **UI 빌더 헬퍼** | 메이커·로비에서 반복되는 드롭다운/버튼/입력 필드 생성 코드를 `SrpUiBuilder` 정적 클래스로 추출 |
| **데이터 유효성 검증** | 맵 로드 시 `disabledSkillIds`·배치 유닛의 스킬 존재 여부 등 체크 + 로그 경고 |
| **저장 경로 정리** | `persistentDataPath` 기반 현행 유지하되, `Resources/SrpMaps/` 읽기 전용 폴백 추가 |

### Phase 2: 스킬 시스템 v2 (2~3주)

> 목표: `PLAN_스킬메이커_개선.md`의 **12단계** 실행

| 단계 | 핵심 |
|------|------|
| **데이터 확장** | `SrpEffectTarget` 분리, `effectTrigger` 오버라이드, `isComponent`·`linkedSkillId` 추가 |
| **메이커 UI 개편** | 효과 순서 재배치, 부품 스킬 UI, 요약 라벨 자동 생성 |
| **전투 적용** | `SrpSkills.ApplyEffects`에서 부품 스킬 해석, 트리거 오버라이드 적용 |
| **마이그레이션** | 기존 JSON 로드 시 `version` 필드 기반 자동 변환 |

### Phase 3: AI 기초 (1~2주)

> 목표: 혼자서도 **플레이테스트** 가능한 AI 상대

| 항목 | 내용 |
|------|------|
| **무작위 합법 수 AI** | 이동 가능 타일 중 랜덤 선택 → 사거리 내 적 랜덤 공격/스킬 사용 |
| **AI 턴 자동 진행** | `Phase` 전환 시 AI 플레이어면 자동 유닛 순회·행동·턴 종료 |
| **난이도 스텁** | "랜덤" 1단계만 우선 구현. 이후 휴리스틱(가까운 적 우선 등) 추가 |

### Phase 4: 콘텐츠 & 밸런스 (지속)

> 목표: 게임으로서의 **재미** 검증

- 기본 제공 맵 3~5종 확대 (지형 다양성: 산악, 실내, 교량)
- 스킬 풀 확장: 힐·버프·디버프·범위 공격·이동기 등 10종+
- 유닛 템플릿 다양화: 탱커·딜러·서포터 아키타입
- 승패 조건 확장 (턴 제한, 거점 점령, 보스전)
- FH(처형장) 확장 규칙 구현
- 밸런스 시트 기반 수치 조정 루프

### Phase 5: 비주얼 고도화 (2~4주)

> 목표: **프로토타입 → 플레이어블 데모** 수준 비주얼

| 항목 | 내용 |
|------|------|
| **타일/유닛 프리팹 전환** | Cube/Cylinder → 모델 or 스프라이트 기반 프리팹 |
| **애니메이션** | 이동·공격·피격·처단 연출 (DOTween 등) |
| **이펙트** | 스킬 사용 시 파티클·카메라 셰이크 |
| **UI 프리팹화** | 코드 생성 UI → 프리팹 기반 + 데이터 바인딩 |
| **사운드** | BGM·SE 기초 시스템 |

### Phase 6: 멀티플레이어 (장기)

> 목표: `SRPG_FUTURE_NETWORK.md` 기반 **원격 2인 대전**

- 액션 커맨드 직렬화 (이동·공격·스킬 사용을 Command 객체화)
- 세션 매칭 (릴레이 서버 or P2P)
- 동기화 검증 (해시 비교)
- 로비 확장 (온라인 매칭 UI)
