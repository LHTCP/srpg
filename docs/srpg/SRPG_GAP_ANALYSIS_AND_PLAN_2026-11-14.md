## 2. 요약

- 기준서 v2의 전투 규칙 골격(속도 라운드, AP 2/RP 1, 태세, 방향, 교전 이탈, 패링, 경계태세, 엄폐, 공용 태그, 쿨다운/충전, 초기 4인 패시브)은 대부분 **브릿지 수치로 구현**돼 있다.
- 크게 비어 있는 것은 규칙 한 줄이 아니라 **플레이 루프**다. 적 AI가 런타임에 없어 양 진영을 사람이 조작하고, 승리 조건은 전멸뿐이며, 그로기는 걸리기만 하고 풀리지 않는다.
- 수치는 거의 전부 `TBD-*` 브릿지다. 특히 근접 PG 피해와 `강타`는 기획 의도(2~3턴에 걸친 PG 붕괴)보다 훨씬 빠르다.
- 자동 검증은 이 PC와 CI 모두에서 Unity로 돌지 않는다. 이번 작업은 저장소 밖 임시 .NET 하네스로 순수 전투 로직과 EditMode 테스트만 실행해 확인했다(8절).

### 3.2 밸런스 피드백 지시(2026-06-15) 대비

| 지시 | 상태 | 근거와 메모 |
| --- | --- | --- |
| 1. PG 붕괴 → 그로기 → 근접 처단 확정 킬 | 구현 | 위 정정 항목과 같음 |
| 2. 그로기는 1턴 무방비, 다음 활성화에 행동 불가 + PG 회복 | 구현(브릿지) | (해소) `SrpTurnOrder.TryConsumeActivationForGroggyRecovery`, `SrpUnitRuntime.IsPgBroken`/`pgBreakGuard`. 재붕괴 보호를 더했다(Q1, Q2 결정) |

### 3.3 기준서에 직접 적히지 않았지만 플레이에 걸리는 것

| 항목 | 상태 | 근거와 메모 |
| --- | --- | --- |
| 적 AI | 부분 | (해소 중) `SrpEnemyAi`가 owner 0이 아닌 유닛을 조작한다. 기본 공격/피해 스킬/이동/재장전과 총기 역할의 경계태세를 쓴다. 태그·회복 스킬, 엄폐, 상호작용은 쓰지 않는다 |

| 맵 메이커 엄폐 segment 편집 | 미구현 | 백로그 미완료 항목 그대로 |

## 4. 1차 개선 내역 (이번 작업)

이미 구현된 것 중 기획과 어긋나거나 명백히 잘못 동작하던 것만 고쳤다. 새 규칙이나 수치 변경은 없다.

| 변경 | 근거 | 테스트 |
| --- | --- | --- |
| 회피(또는 패링)로 무효화된 공격에는 "공격 적중 시" 패시브를 발동하지 않는다. `SrpSkills.OnAttackResolved` | 기준서 §10 `전장 적응`/`노출 처벌`은 "공격 적중 시". 빗나간 사격에도 안정도가 올랐다 | `SrpCombatResolverTests.OnAttackResolved_DodgedAttackDoesNotTriggerOnHitPassive` |
| 스킬로 적을 처치하면 교전 상태를 즉시 다시 계산한다. `SrpSkills.ApplyEffects` | 죽은 유닛이 교전 목록에 남아 수비 지속 완충, 탱커 다중 교전 완충, 교전 이탈 비용이 다음 이동/라운드까지 잘못 계산됐다(`RQ-010`) | `SrpCombatResolverTests.ResolveActiveSkill_KillRebuildsEngagements` |
| 스킬 피해도 대상의 "피격 시" 패시브를 발동한다. `SrpSkills.ApplyEffects` | 기준서 §10 `전열 고정`은 "피격 후 PG +2". 기본 공격·경계사격·기회공격에만 발동하고 스킬 피해에는 빠져 있었다 | `SrpCombatResolverTests.ResolveActiveSkill_DamageTriggersTargetOnTakeDamagePassive` |
| AP를 쓴 뒤에는 태세를 바꿀 수 없다. `SrpGameController.CanSetSelectedStance` | 기준서 §4 "턴 중 자유 변경 없음". 엄폐·상호작용은 전용 플래그가 없어 그 뒤에 태세 변경이 가능했다 | 자동 테스트 없음(컨트롤러). 8절 체크리스트 |
| 시뮬레이션에서 이동·처치 후 교전 상태를 다시 계산한다. `SrpBattleSimRunner` | 시뮬레이션은 시작 시점 교전 상태를 끝까지 썼다. 실제 전투 흐름과 맞춘다 | 기존 `SrpM1AiSimAllEntry` 3종. 지표 변화는 미미(예: 첫 전투 Heuristic vs Random 평균 8.57 → 8.55 라운드) |
| `SrpCombatResolverTests`에 `[Category("SrpM1All")]` 추가 | 카테고리 필터 실행에서 이 묶음이 통째로 빠져 있었다 | - |

## 5. 단계별 진행 계획

우선순위는 "한 판을 끝까지 의도대로 플레이할 수 있는가"를 기준으로 잡았다. 각 단계는 앞 단계의 기획 결정에 의존한다.

### 1차. 구현된 것의 검토와 개선 — 이번 작업

- 완료 기준: 4절 변경이 테스트와 함께 들어가고, 갭과 질문이 문서로 남는다.
- 남은 일: Unity에서 컴파일·EditMode·PlayMode 확인(8절).

### 2차. 그로기 1턴 무방비와 회복 — 완료(브릿지)

- 반영한 규칙: 그로기 유닛은 다음 활성화를 잃고 PG를 35% 회복한다. 회복 후 그다음 자기 활성화까지 재붕괴 보호(PG 1 유지)를 받는다. 그로기 중에는 반응을 하지 못한다. 기준서 "2026-11-14 브릿지" 절.
- 고착 확인: 재붕괴 보호만으로는 시뮬레이션 미러전이 여전히 무승부였다. 좁은 통로의 1대1 근접전은 혼자서 처단할 수 없고 근접 HP 피해가 작아서다. 시뮬레이션 AI가 재장전과 피해 스킬을 쓰게 하자(3차의 적 AI) 미러전이 6~7라운드에 끝났다. 수치는 `SRPG_IMPLEMENTATION_DECISIONS.md` 2026-11-14 절.
- 아래는 착수 전 기록이다.

- 대상: 3.2의 지시 2. `SrpTurnOrder`, `SrpGameController.AdvanceToNextActivation`, `SrpCombatResolver` 반응 조건, `SrpBattleSimRunner`.
- 선행 결정: 질문 Q1, Q2.
- 이번에 넣지 않은 이유: 지시서대로 "다음 활성화 스킵 + PG 35% 회복"을 시험 구현해 시뮬레이션을 돌리니 전투가 고착됐다. 근접 한 방이 회복된 PG를 다시 0으로 만들기 때문에, 공격자 한 명이 대상을 매 라운드 재붕괴시키고 대상은 영영 행동하지 못한다. `M1QaIntegrated` Heuristic 미러전은 무승부 0% → 100%(24라운드 상한), 회복량을 100%로 올려도 평균 7 → 19라운드였다. 근접 PG 수치(3.2의 5번)와 함께 정하지 않으면 규칙만 넣어서는 안 된다.
- 완료 기준: 그로기 유닛이 다음 활성화에 행동하지 못하고 회복한다. 한 명이 대상을 무한히 묶는 고착이 시뮬레이션에서 재현되지 않는다. EditMode 테스트로 회복 타이밍·회복량·재붕괴 조건을 고정한다. 임계치(`SrpSimThresholds`)를 통과한다.
