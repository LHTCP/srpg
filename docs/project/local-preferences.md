# 로컬 전용 작업 취향 설정

이 문서는 **저장소에 커밋하지 않는 로컬 전용 작업 취향**을 다룬다.

## 목적

사람마다 선호하는 작업 방식이 조금씩 다를 수 있다.

예:

- 작업 하나당 작은 PR 하나로 바로 지속 통합
- 이슈 / PR / 커밋 메시지 언어 선호
- 워크트리 루트 경로 고정
- 로컬에서 `main` 직접 작업 금지
- 비자명한 변경에 셀프리뷰 라인 코멘트 남기기
- 셸/CI 스크립트에 의도 주석을 풍부하게 남기기

이런 설정은 팀 공통 규칙과는 별개로, **현재 로컬 환경에서만 적용되는 선호값**으로 두는 편이 안전하다.

## 파일 구성

- 예시 파일: `project.local.example.json`
- 실사용 파일: `project.local.json`

`project.local.json`은 `.gitignore`에 포함되어 있으므로 저장소에 올라가지 않는다.

## 시작 방법

1. `project.local.example.json`을 참고한다.
2. 같은 위치에 `project.local.json`을 만든다.
3. 현재 로컬에서 원하는 작업 취향으로 값을 수정한다.

예:

```json
{
  "workflow": {
    "integrationStyle": "small-pr-continuous-integration",
    "preferPrPerTask": true,
    "defaultIssueLanguage": "ko",
    "defaultPrLanguage": "ko",
    "defaultCommitLanguage": "ko"
  }
}
```

## 권장 용도

- PR 단위 선호
- 언어 선호
- 워크트리 루트 경로
- 로컬 브랜치 보호 습관
- 로컬 스크립트 기본 옵션
- 셀프리뷰 코멘트 선호
- 스크립트 주석 밀도 선호

## 비권장 용도

- 비밀값, 토큰, 인증서
- 팀 전체가 따라야 하는 공식 정책
- CI가 반드시 알아야 하는 설정

이런 값은 각각 GitHub Secrets, 저장소 문서, 워크플로 파일 쪽에서 관리한다.

## 이 프로젝트에서의 권장 기조

현재 프로젝트에서는 다음 로컬 취향이 잘 맞는다.

- 작은 작업 단위 PR 선호
- GitHub 중심 통합
- 이슈 / PR / 커밋 메시지는 한국어 선호
- 영어 커밋 메시지를 쓰는 경우 명령형 선호
- `worktrees/` 기반 병렬 작업
- 비자명한 라인 변경에는 셀프리뷰 코멘트 남기기
- 셸/CI 스크립트는 다음 사람이 의도를 바로 알 수 있게 주석을 넉넉히 남기기

## 에이전트와의 관계

에이전트가 로컬 저장소에서 작업할 때 `project.local.json`이 있으면, 저장소 공통 규칙과 충돌하지 않는 범위에서 **로컬 선호값**으로 참고할 수 있다.

공통 규칙보다 우선하는 것은 아니다. 우선순위는 다음과 같다.

1. 저장소 문서와 공식 정책
2. 현재 요청의 명시적 지시
3. `project.local.json`의 로컬 취향
