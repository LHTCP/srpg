# 문서화 규칙

## 문서 전용 위치 (`docs/`)

**마크다운 문서(`.md`)는 `Assets/` 밖, 저장소 루트의 `docs/` 아래에만 둔다.** 코드·씬과 같은 폴더에 장문 가이드를 두지 않는다.

### 범주(폴더) 구분

| 폴더 | 용도 |
|------|------|
| `docs/project/` | 프로젝트 공통 — Git·워크플로, 세팅, 워크트리, 이 문서(작성 규칙) |
| `docs/srpg/` | SRPG 기획·기술·실행 메모 |
| `docs/README.md` | 전체 문서 인덱스(진입점) |

새 도메인이 생기면 `docs/<이름>/` 폴더를 만들고, [README.md](../README.md) 표에 한 줄 추가한다.

## 문서 계층

- 전체 진입점은 `docs/README.md`다.
- 도메인별 문서가 늘어나면 `docs/<도메인>/README.md`를 두고 현재 기준, 실행 플랜, 과거 문서를 분리한다.
- 작업 처리 방식은 [work-contract.md](work-contract.md)를 따른다.
- 현재 기준 문서와 과거 원문이 충돌하면 현재 기준 문서를 우선한다.

## 루트 `AGENTS.md`

- 사람·에이전트용 **한 페이지 진입점**만 둔다. 장문 본문은 `docs/`에 쓴다.

## 파일 이름

- 폴더별 `README.md`는 선택(해당 범주 요약이 필요할 때만).
- 주제별: `주제_가이드.md`, `SRPG_TDD.md` 등 식별 가능한 이름을 쓴다.
- 같은 내용을 두 파일에 복붙하지 않는다.

## Unity·Git

- 문서를 `docs/`에만 두므로 **Unity `.meta`는 생성되지 않는다** (에셋 GUID와 무관).
- 코드나 스크립트 경로를 문서에 적을 때는 실제 `Assets/...` 경로를 그대로 적는다.

## 톤

- `docs/project/`는 건조하고 짧게.
- 기능 가이드는 단계별·교육용 톤을 써도 된다.

## 언제 갱신하는가

- 매니저의 **public API**·인스펙터 노출 필드가 의미 있게 바뀌면: 해당 범주 문서 또는 `AGENTS.md`의 실행 요약에 영향이 있으면 같이 수정한다.
- 요구사항 ID, 백로그 우선순위, QA 커버 상태가 바뀌면: 해당 도메인의 README, 백로그, 추적표, 변경 이력을 함께 확인한다.
