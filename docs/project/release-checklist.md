## 배포 전 체크리스트

배포 전에는 "빌드가 만들어지는가"보다 "누가 어떤 버전을 플레이하게 되는가"를 먼저 확인한다.

- [ ] 배포 대상 브랜치 또는 태그가 명확하다.
- [ ] 배포 대상 커밋 SHA를 릴리스 기록에 남길 준비가 되어 있다.
- [ ] `main` 기준 컴파일 오류가 없거나, 남아 있는 오류를 known issue로 기록했다.
- [ ] GitHub Actions 필수 체크가 모두 통과했다.
- [ ] `Delivery 선행 헬스체크` workflow가 통과했다.
- [ ] Unity EditMode/PlayMode 테스트 실행 결과를 확인했다.
- [ ] LFS, Unity license, 플랫폼별 signing secret이 필요한 workflow에서 정상적으로 접근 가능한지 확인했다.
- [ ] PC/Windows 배포 대상과 산출물 위치를 명시했다.
- [ ] 이번 배포에서 제외되는 플랫폼이 있으면 제외 사유를 릴리스 노트에 남겼다.
- [ ] 새로 추가된 gameplay 변경, UI 변경, 저장 데이터 변경, 설정 변경이 smoke test 항목에 반영되어 있다.
- [ ] 배포 실패 시 재실행할 workflow와 담당자가 명확하다.
- [ ] rollback 기준과 known issue 기록 기준을 배포 전에 합의했다.

## 배포 후 smoke test 체크리스트

배포 후 smoke test는 장시간 QA가 아니라 "최신 배포물을 플레이 가능한 상태로 받을 수 있는가"를 확인하는 최소 검증이다.

### 공통

- [ ] 배포 링크 또는 artifact 다운로드 경로에 접근할 수 있다.
- [ ] 배포물이 의도한 커밋 SHA 또는 릴리스 태그에서 생성되었음을 확인했다.
- [ ] 실행 중 치명적인 로딩 오류나 시작 즉시 크래시가 없다.
- [ ] 메인 진입 화면이 정상적으로 표시된다.
- [ ] 핵심 씬 전환 또는 전투 진입 흐름을 최소 1회 확인했다.
- [ ] 텍스트가 읽기 어려울 정도로 깨지거나 누락되지 않는다.
- [ ] 입력 장치 기준이 배포 대상에 맞게 동작한다.
- [ ] 확인한 환경, 브라우저, OS, 기기 정보를 릴리스 기록에 남겼다.

### PC/Windows

- [ ] `Windows PC 데모 빌드` workflow에서 생성된 `srpg-demo-windows-<version>-<short-sha>` artifact를 다운로드할 수 있다.
- [ ] GitHub artifact zip 안의 실제 게임 zip을 구분해 압축 해제했다.
- [ ] itch.io 게시 대상이라면 내부 실제 게임 zip을 업로드했다.
- [ ] 압축 해제 후 실행 파일이 시작된다.
- [ ] Windows 보안 경고나 차단이 있으면 릴리스 기록에 남긴다.
- [ ] 최소 1개 전투 또는 핵심 플레이 루프를 실행한다.

### WebGL 보조 후보

- [ ] TODO: 확정된 WebGL URL에서 최신 빌드가 열린다.
- [ ] 브라우저 콘솔에 치명적인 에러가 반복되지 않는다.
- [ ] 첫 로딩 시간이 비정상적으로 길지 않다.
- [ ] 새로고침 후에도 동일하게 실행된다.

### 모바일 보류

- Android, iOS, TestFlight, Google Play, App Tester 배포는 크로스플랫폼 지원 결정 전까지 릴리스 체크리스트의 완료조건으로 삼지 않는다.
- 모바일이 별도 기획 아이템으로 승격되면 계정, 서명, 비용, 테스트 채널 접근권한을 새 decision 이슈에서 다시 검토한다.

## rollback 기준

다음 중 하나에 해당하면 기본적으로 rollback 또는 배포 중단을 검토한다.

- 최신 배포물이 실행되지 않거나 시작 직후 크래시가 발생한다.
- 핵심 씬 진입, 전투 시작, 입력 처리 중 하나가 막혀 플레이가 불가능하다.
- 이전 정상 배포보다 데이터 손상, 설정 손상, 진행 불가 위험이 커졌다.
- 배포 링크가 잘못된 커밋 또는 잘못된 플랫폼 산출물을 가리킨다.
- secret, signing, LFS credential이 로그에 노출되었거나 노출 가능성이 있다.
- known issue로 안내하기에는 사용자 영향이 크고 우회 방법이 없다.

rollback을 수행하면 다음 정보를 남긴다.

- rollback 판단 시간
- 문제를 발견한 배포 버전, 커밋 SHA, 플랫폼
- 되돌릴 대상 버전 또는 이전 정상 artifact
- 사용자가 이미 받은 빌드에 대한 안내 필요 여부
- 후속 수정 이슈 또는 PR 링크

## known issue 기록 기준

known issue는 "문제가 있지만 이번 배포를 막지는 않는다"는 판단을 명시하는 기록이다.

known issue로 기록할 수 있는 예시는 다음과 같다.

- 특정 브라우저 또는 특정 OS에서만 발생하고 우회 방법이 있다.
- UI 표시 품질 문제지만 핵심 플레이 흐름은 가능하다.
- 테스트 채널 접근 권한처럼 운영 설정으로 해결 가능하며 플레이 데이터 손상 위험이 없다.
- 이미 별도 GitHub issue로 추적 중이고 다음 릴리스에서 수정할 계획이 있다.

known issue로 기록하면 다음 정보를 포함한다.

- 증상
- 영향 플랫폼
- 재현 조건
- 사용자 우회 방법
- 추적 GitHub issue
- 다음 확인 시점

known issue로 처리하지 말아야 할 예시는 다음과 같다.

- 실행 불가, 시작 즉시 크래시, 핵심 전투 진입 불가
- 사용자가 저장 데이터나 설정을 잃을 수 있는 문제
- 배포 산출물의 출처나 버전을 신뢰할 수 없는 문제
- secret, 인증서, 계정 정보 노출 가능성이 있는 문제

## 릴리스 기록 템플릿

아직 릴리스 노트 위치가 확정되지 않았으므로, 임시 기록은 GitHub issue 또는 PR 댓글에 남긴다.

```md
## 릴리스 기록

- 배포 일시:
- 배포 대상:
- 커밋 SHA:
- 플랫폼:
- 빌드 workflow:
- artifact 또는 플레이 링크:
- itch.io 페이지:
- smoke test 결과:
- known issue:
- rollback 필요 여부:
- 후속 이슈:
```
